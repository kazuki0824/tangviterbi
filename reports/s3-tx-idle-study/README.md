# ② SPI線路の停止原因

最新のcounter費用模型に観測だけを追加した。元の仮想時刻・停止bank・費用・payload検算結果との一致を確認し、時刻区間を各portで重複なく分類した。RF開始前の時間は含まない。

S6/16・BCPA・準備2048語・609bank条件：

|分類|SPI2|SPI3|
|---|---:|---:|
|線上転送中|80.906%|86.910%|
|投入・開始処理中|5.360%|2.867%|
|公開データあり・未送信|11.645%|9.366%|
|先頭bank完成・collect待ち|0.426%|0.116%|
|公開待ち（上記以外）|1.663%|0.741%|

公開データの有無は共通prefixに対する判定である。両portの割合を足して、そのまま削減可能時間や帯域増加とは解釈しない。公開待ちには初回立上がりと、部分的に完成していてもbank全体では未完成の時間も含む。観測模型の区間分類で、実機計測ではない。

これを根拠に、完了回収を待たずに次の公開済みpayloadを投入できる深さ2のqueue候補を実装した。[候補と期限評価](../s3-queue-study/README.md)。再現：`python -m experiments.s3_tx_idle_study`。[全数値](results.json)。
