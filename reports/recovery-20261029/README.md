# ② 中断判断のリカバリー

目的は、完了条件を満たす前に「説明・検算成功・Push」を終了条件に置き換える再発を防ぐこと。元の依頼は変更しない。①には触れない。

1. [作業台帳](plan.json)に元の終了条件、残項目、次の具体的操作、根拠を保存する。未実装や未測定だけで全項目をblockedにしない。
2. 状態を機械確認する。`python -m ci.s3_recovery_status` は今実行できる項目を返す。`--claim-complete` は未完了が残れば終了code 2で完了宣言を拒否する。
3. 状態確認後、ready項目を実行する。今回、64bitカウンタ費用の全分岐監査・実Cの完了順序検算、およびハードウェア待ち反復の単価監査に着手した。
4. 新しい費用はCPU台帳と時刻模型へ同額を一度だけ課し、RF監視・送信・容量判定を再実行する。結果と未完了状態を②のPRへ反映する。
5. 途中報告は作業中に行う。質問への説明だけで継続指示を終了扱いにしない。中断が必要なら目的と根拠、残る実行可能項目を分けて記す。

このスクリプトは完了宣言の整合検査で、会話の終了を技術的に禁止する機能ではない。再発しない保証をしたとは扱わない。また、管理表を作ったことと元の技術課題の完了は別である。
